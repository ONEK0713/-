## 1. 背景与目标

### 1.1 背景

本地音乐文件散落在多个文件夹中，主流播放器普遍存在体积大、广告多、强制登录、依赖在线曲库的问题。用户需要一个"只播放我自己的文件"的轻量工具。

### 1.2 产品目标

做一个**纯本地、免登录、离线可用**的音乐播放器：打开、导入、点一下就听。

### 1.3 成功标准（MVP）

- 新用户从打开到播放第一首歌 ≤ 1 分钟
- 刷新当前标签页后曲库还在；关掉标签页重新打开是干净的，不残留上次的曲库
- 1000 首曲库下列表与播放保持流畅（标签解析不阻塞列表）
- 断网状态下功能完整可用

### 1.4 非目标

不做在线曲库、账号体系、云同步、社交分享、多端同步。

## 2. 目标用户与场景

**目标用户**：拥有个人本地音乐收藏（MP3 / FLAC 等），希望轻量播放、不想被账号和广告打扰的用户。

**典型场景**：

1. 工作或写代码时按列表顺序听背景音乐
2. 按专辑顺序完整聆听（导入顺序即专辑顺序）
3. 想听某首歌时快速搜索并播放
4. 刷新页面（比如改完样式、重启开发服务器）后继续听

## 3. 产品定位

> 一个不需要登录、不联网、打开就能听本地音乐的播放器。

**形态**：本地 Web 应用（Vite + React + TypeScript），在浏览器中运行；后续可封装为桌面应用。

## 4. MVP 范围

理由：每一项都能独立吃掉一周以上，且不解决"能不能好好听歌"。

## 5. 核心流程

1. 首次打开 → 空态引导 → 点「导入音乐」选文件夹（或把文件夹拖进窗口）
2. 扫描并解析 → 占位行先出现，标签与时长逐行填上
3. 点击歌曲 → 播放；播放条显示封面、标题、歌手、进度、音量
4. 播放中：暂停、上下曲、拖进度、调音量、搜索过滤、移除（可撤销）
5. 刷新页面 → 曲库还在；关掉标签页再打开 → 空的

## 6. 功能说明

### 6.1 曲库导入

- **入口**：顶部（以及空态）的「导入音乐」按钮，展开两项——「选择文件夹」「选择文件」；拖拽文件或文件夹到窗口任意位置同样有效
- **行为**：递归扫描目录（最多 12 层，跳过隐藏目录与 `node_modules` 一类目录）；识别 mp3 / flac / m4a / aac / wav / ogg；非音频文件忽略并汇总数量
- **反馈**：占位行先插入列表，标签逐行补齐；每 5 首报一次「正在读标签 x/y」；结束时汇总成功数与读不到标签的数量
- **去重**：按「相对路径 + 大小 + 修改时间」判重，同一文件重复导入不会产生第二行；不同目录下的同名文件不会被并成一首
- **标签清洗**：ID3v2 声明 ISO-8859-1 实写 GBK 的文件（如 `08.罗庄的冬天.mp3`）会自动纠正成 `罗庄的冬天 / 李志 / 被禁忌的游戏`
- **封面**：按内容指纹（FNV-1a）去重后存 IndexedDB。一张碟里 9 首歌各存了两份相同的封面，实际只落一份
- **边界**：空文件夹、全是非音频、解析失败 → 跳过并汇总，不中断导入

### 6.2 曲库浏览与搜索

- **列表字段**：序号、标题、歌手、专辑、时长；封面只在播放条展示
- **顺序**：默认按导入顺序；点表头可按标题 / 歌手 / 专辑 / 时长排序，点一下升序、再点降序、第三下回到导入顺序。中文按拼音序，数字按数值比较，空值始终排最后
- **搜索**：即时过滤，匹配标题 / 歌手 / 专辑，忽略大小写与首尾空格
- **移除**：行尾按钮移除单曲，只影响当前列表，不碰磁盘文件；5 秒内可撤销，内容恢复回原位置；再次导入这首歌会直接进来，不做任何"已删除"记忆
- **清空**：顶栏「清空曲库」要点两下确认（3 秒内不点自动退回），清空后刷新也不会回来
- **大曲库**：超过 150 首切换成虚拟滚动，只渲染视口附近约 30 行；搜索或排序把列表变短后自动回到全量渲染

### 6.3 播放控制

- 播放 / 暂停、上一首 / 下一首（到两端按播放模式处理）
- 进度条：显示当前时间与总时长，可拖拽 seek
- 音量：滑块，范围 0–100%；点喇叭图标静音 / 取消静音；音量调到 0 再调回来会自动解除静音
- 错误：这一首放不了时提示「浏览器不支持该编码」，不自动跳下一首
- 自动播放：受浏览器策略限制，首次播放必须由用户点击触发

**快捷键**（焦点在输入框或滑杆里时不生效）：

| 按键 | 作用 |
| --- | --- |
| 空格 | 播放 / 暂停 |
| ← / → | 后退 / 前进 5 秒（按住 Shift 为 30 秒） |
| Ctrl + ← / → | 上一首 / 下一首 |
| ↑ / ↓ | 音量 +5% / −5% |
| M | 静音 / 取消静音 |
| `/` | 聚焦搜索框 |
| Esc | 从搜索框退出来 |

### 6.4 播放顺序

- 四种模式，播放条右侧按钮循环切换：顺序播放 → 列表循环 → 单曲循环 → 随机播放
- **顺序播放**：播到最后一首停止，提示「曲库放完了」
- **列表循环**：最后一首之后回到第一首
- **单曲循环**：当前这首放完再放一遍；手动点下一首仍然换歌（否则这个按钮就没用了）
- **随机播放**：每次挑一首不同的（不会连续放同一首）；手动「上一首」仍按列表往前
- 模式选择写在本机（`localStorage`），刷新和下次打开都记得；这一项不需要文件句柄，不涉及隐私
- 不提供队列抽屉：移除正在播放的那首 → 播放器停下，回到「未播放」

### 6.5 状态与刷新语义

- **刷新页面**：曲库保留。机制是 `sessionStorage` 里一个"这个标签页还活着"的标记 + IndexedDB 里的来源句柄（`sources` store），刷新时按句柄把文件重新读出来
- **关掉标签页 / 浏览器后再打开**：`sessionStorage` 随标签页销毁，启动时看不到标记，于是清掉残留的句柄与标签缓存，列表是空的
- **不跨会话保存**：上次曲目与播放进度不保存（PRD 早期版本的"第二天继续上次进度"已放弃，因为它需要跨会话句柄授权，用户明确不要）。音量与播放模式是纯偏好、不涉及文件访问，单独存在 `localStorage` 里
- **失效来源**：刷新时读不到的目录会从清单里剔除并回写，全部失效时提示「上次的曲库读不到了，重新选一次文件夹吧」
- **清空**：清空曲库时同时清掉标签缓存、封面缓存、来源句柄与会话标记

### 6.6 状态与反馈

- **空态**：说明支持哪些格式、ape / wma / dsd 放不了，并说明刷新与关闭的差别
- **加载态**：导入进度、"正在读标签 x/y"
- **提示条**：3.2 秒自动消失；带「撤销」的留 5 秒
- **错误态**：解码失败、文件夹读取失败、目录已失效
- **离线**：无网络不影响任何功能

## 7. 界面结构

单页两区：主区（搜索 + 曲库列表）与底部播放条。

```
┌──────────────────────────────────────────────────┐
│ ♪ 本地音乐  N 首   🔍 搜索     [导入音乐 ▾] [清空] │
│ ──────────────────────────────────────────────── │
│ #  标题      歌手      专辑      时长             │
│ ▶  ...                                       ✕   │
│   ...                                            │
├──────────────────────────────────────────────────┤
│ [封面] 歌名 · 歌手  ⏮ ⏯ ⏭  ──●── 2:31/4:05  🔊  │
└──────────────────────────────────────────────────┘
```

**简洁原则**：

- 一屏完成导入、搜索、播放，不做页面跳转
- 播放条信息克制：封面、标题、歌手、必要控件
- MVP 不引入多级菜单和弹窗式设置（唯一的弹出层是导入方式两项）

## 8. 非功能需求

- **性能**：列表滚动 60fps（150 首以上走虚拟滚动，DOM 里只有几十行）；本地切歌 < 100ms；缓存命中时首屏 < 1s；标签解析不阻塞主线程
- **兼容**：Chrome / Edge 最近两个大版本走 File System Access（拿得到真实相对路径，刷新可恢复）；Firefox / Safari 退回 `<input webkitdirectory>` 与多选文件，能导入能播放，但刷新后无法自动恢复
- **隐私**：不上传文件与元数据，无遥测，无账号
- **离线**：完全离线可用
- **可访问性**：列表行与按钮均可键盘操作，焦点可见，提示条用 `role="status"`
- **数据**：移除与清空只影响内存和浏览器缓存，不触碰源文件

## 9. 技术方案概要

- **前端**：Vite 8 + React 19 + TypeScript 7（strict、`noUncheckedIndexedAccess`）；状态用 React hooks 按领域拆成 `useLibrary` / `usePlayback` / `useImports` / `useNotice` / `useShortcuts` / `useVirtualRows`，没有引入状态库
- **音频**：单个 `HTMLAudioElement` + `URL.createObjectURL`；不上 Web Audio
- **播放决策**：`play-mode.ts` 里两个纯函数 `nextTrackIndex` / `stepIndex` 决定下一首是谁，随机源可注入，边界条件全部有单测
- **偏好**：`settings.ts` 读写 `localStorage` 里的音量与播放模式，坏数据退回默认值
- **排序**：`Intl.Collator('zh-Hans-CN', { numeric: true })` 做中文拼音序与数字序，纯函数 `sortTracks` / `nextSort`
- **虚拟滚动**：行高固定 54px，`visibleRange` 纯函数算区间，`useVirtualRows` 负责测量滚动容器并在 `requestAnimationFrame` 里合并滚动事件
- **元数据**：`music-metadata` 12 的 `parseBlob`，跑在 3 个模块 Worker 里；Worker 不可用时降级到主线程（测试环境走这条）；`music-metadata` 用动态 import，不进主包
- **编码兜底**：`TextDecoder('gbk')` 重解码 + 中文比例打分，只在"看起来像错误的 Latin-1"时才动手，避免改坏 `Café` 这类正常文本
- **封面**：两路 FNV-1a 内容指纹，存 IndexedDB `covers` store，按指纹去重
- **存储**：IndexedDB（`local-player` v4：`tags` / `covers` / `sources`）+ `sessionStorage` 会话标记 + `localStorage` 两项偏好
- **目录访问**：File System Access（`showDirectoryPicker` / `showOpenFilePicker`）+ `<input webkitdirectory>` 双适配，统一收敛成 `{ file, path }`
- **测试**：Vitest + Testing Library，131 个用例，覆盖导入、解析缓存、移除撤销、刷新恢复、封面回退、播放模式与快捷键、排序、虚拟区间，以及纯函数（时间格式、搜索、并发、句柄转换）
- **运行**：固定端口 `8787`（`--strictPort`）。IndexedDB 与句柄按 origin 隔离，换端口等于换一个空曲库；`dev.cmd` 双击启动

## 12. 风险与对策

| 风险 | 影响 | 对策 |
| --- | --- | --- |
| File System Access 仅 Chromium 支持 | 其他浏览器刷新后恢复不了 | 降级到 `<input webkitdirectory>`；空态说明刷新/关闭的差别 |
| 首次扫描慢 | 体验差 | 占位行先上、标签边解析边填、IndexedDB 缓存 |
| 标签缺失或乱码 | 信息错误 | 文件名兜底 + GBK 重解码 |
| 大文件 / 损坏文件 | 播放失败 | 跳过并提示，不影响其它曲目 |
| 浏览器自动播放限制 | 首次播放无声 | 必须用户点击；错误提示引导再点一次 |
| 换端口 / 清站点数据 | 曲库与缓存全丢 | 固定 8787；文档说明 |
